================================================================
PLAYER HISTORY — ADMIN API
For: admin site, "view a player's history" screen
Auth: Admin JWT required on every request.
      Header:  Authorization: Bearer <ADMIN_JWT>
================================================================

There are TWO independent feeds for a player:

  1. TRANSACTION HISTORY  → money movement (deposits + withdrawals)
  2. BETTING HISTORY      → wagers across Lottery / Jackpot / Slots

Both take the target player via `userId`. They are separate
endpoints with separate response shapes — render as two tabs.


================================================================
1) TRANSACTION HISTORY
================================================================

GET /wallet/admin/transactions

Query params:
  userId   (required, int)   the player to view
  page     (optional, int)   default 1
  limit    (optional, int)   default 20, max 100
  type     (optional, str)   "DEPOSIT" | "WITHDRAWAL"
                             omit = both

This is the money-movement statement only: deposits and
withdrawals. Bets / wins / bonuses are NOT here — those are in
the betting feed (section 2).

Example:
  GET /wallet/admin/transactions?userId=42&page=1&limit=20
  GET /wallet/admin/transactions?userId=42&type=DEPOSIT

Response 200:
{
  "data": [
    {
      "id": 9981,
      "ledger_code": "LDG-AB12CD",
      "entry_type": "DEPOSIT_APPROVED",
      "flow": "CREDIT",
      "amount": "500.00",
      "balance_before": "1200.00",
      "balance_after": "1700.00",
      "reference_type": "DEPOSIT",
      "reference_id": 551,
      "status": "SUCCESS",
      "description": "Deposit approved by admin",
      "created_by_type": "ADMIN",
      "created_at": "2026-06-09T11:24:31.000Z",
      "typeLabel": "DEPOSIT",
      "walletType": "bKash",        // deposits only; else null
      "agentNumber": "017XXXXXXXX", // deposits only; else null
      "gatewayName": "bKash"        // deposits only; else null
    }
    // ... more rows, newest first
  ],
  "page": 1,
  "limit": 20,
  "total": 37,
  "totalPages": 2
}

Field notes:
  entry_type   one of:
                 DEPOSIT_PENDING, DEPOSIT_APPROVED, DEPOSIT_REJECTED,
                 MANUAL_DEPOSIT,
                 WITHDRAWAL_REQUESTED, WITHDRAWAL_APPROVED, WITHDRAWAL_REJECTED
  typeLabel    pre-formatted label to display. Admin labels include
                 "DEPOSIT", "WITHDRAWAL", "MANUAL DEPOSIT", "MANUAL ADJUST".
                 ^ use this for the UI; entry_type is the raw enum.
  flow         CREDIT | DEBIT | LOCK | RELEASE
  status       PENDING | SUCCESS | FAILED
  amount, balance_*   come back as STRINGS (numeric). Parse to number
                      before doing math.
  walletType / agentNumber / gatewayName
               populated for deposit rows only (where the player paid);
               null for withdrawals.


================================================================
2) BETTING HISTORY
================================================================

Primary:
GET /admin/game-history

Query params:
  userId    (required, int)   the player to view
  category  (optional, str)   "LOTTERY" | "JACKPOT" | "SLOT"  (omit = all)
  status    (optional, str)   "WON" | "LOST" | "PLACED" | "CANCELLED"
  from      (optional, str)   ISO date, inclusive   e.g. "2026-05-01"
  to        (optional, str)   ISO date, inclusive (covers whole day)
  page      (optional, int)   default 1
  limit     (optional, int)   default 20, max 100

IMPORTANT: if `from` is omitted it defaults to the LAST 7 DAYS.
Always send an explicit `from`/`to` from the date picker.

Example:
  GET /admin/game-history?userId=42&from=2026-05-01&to=2026-06-01
  GET /admin/game-history?userId=42&category=SLOT&status=WON&from=2026-05-01&to=2026-06-01

Combined timeline (all products + all statuses, date-filtered only):
GET /admin/game-history/combine?userId=42&from=2026-05-01&to=2026-06-01

Response 200 (same shape for both routes):
{
  "statusCode": 200,
  "message": "Game history",
  "data": [
    {
      "refId": "12345",
      "refCode": "BET-AB12CD",
      "category": "LOTTERY",       // LOTTERY | JACKPOT | SLOT
      "gameCode": "3D",
      "gameName": "3D Lottery",
      "providerId": null,          // set for SLOT only
      "providerName": null,        // set for SLOT only
      "betNumber": "123",          // null for slots
      "betAmount": 50,
      "payoutMultiplier": 800,     // null for slots
      "potentialPayout": 40000,    // null for slots
      "actualPayout": 0,           // amount won (0 if lost, null if pending)
      "status": "LOST",            // WON | LOST | PLACED | CANCELLED
      "placedAt": "2026-05-12T09:00:00.000Z",
      "settledAt": "2026-05-12T12:00:00.000Z",
      "roundCode": "RND-7781",
      "resultNumber": "456"        // null until drawn
    }
    // ... more rows, newest first
  ],
  "page": 1,
  "limit": 20,
  "total": 128,
  "totalPages": 7,
  "window": { "from": "2026-05-01T...", "to": "2026-06-01T..." },
  "summary": {
    "totalBets": 128,
    "totalWins": 12,
    "totalLosses": 110,
    "totalPending": 4,
    "totalCancelled": 2,
    "totalStaked": 6400,
    "totalWon": 9800,
    "netPL": 3400          // totalWon - totalStaked (player's net)
  },
  "byCategory": [
    {
      "category": "LOTTERY",
      "totalBets": 80, "won": 6, "lost": 72, "placed": 1, "cancelled": 1,
      "staked": 4000, "won_amount": 5000, "netPL": 1000
    }
    // ... one row per category present
  ]
}

Field notes:
  numeric fields here are already JSON numbers (not strings).
  actualPayout = null while status is PLACED (not yet settled).
  netPL is from the PLAYER's perspective (positive = player up).


================================================================
UI SUGGESTION
================================================================
Player detail page → two tabs:
  • "Transactions"  → GET /wallet/admin/transactions?userId={id}
                      paginate; show typeLabel, amount, status,
                      balance_after, created_at, gatewayName.
  • "Bets"          → GET /admin/game-history?userId={id}&from=&to=
                      show summary cards (netPL, staked, won) on top,
                      byCategory chips, then the paginated row list.

All amounts in the transaction feed are STRINGS — parseFloat them.
All amounts in the betting feed are NUMBERS already.
